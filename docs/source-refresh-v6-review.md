# Source refresh and HTTP continuation review, 2026-10-25

Scope: the Task 1 and Task 2 runtime delta in the download manager, HTTP probe/resume contract, source replacement preflight, HLS checkpoint identity export, external source binding/base validation, desktop IPC and refresh UI. This was a finite implementation review plus inspection of the targeted regression results, not a new broad audit or release certification.

Verdict: no unresolved P1/P2 findings in this bounded pass after the two fixes below.

| Finding | Resolution verified |
| --- | --- |
| A paused HTTP partial larger than the declared resource could retain a trailing byte and be published as completed. | Preparation now rejects a partial larger than the saved total before opening it for writes. The regression expands the file to `totalBytes + 1`, expects failure and compares every retained byte. |
| A legacy DASH cache without a recorded manifest base could mix old fragments with resources resolved against a new redirect location. | Continuation refuses a missing base when the saved state contains files or positive progress, before extractor startup, reconciliation or checkpoint replacement. The regression covers the unchanged URL and a redirect to another directory, checks that no extractor marker appears, and compares all cache files including metadata byte for byte. An empty legacy state with no files/progress may establish its first base; its regression proves extraction is reached without changing cache on extraction failure. |

The final HTTP size check considers only segments with positive received bytes when computing the required on-disk extent. A future range that has received nothing does not require a sparse extent to exist. The four-connection regression pauses with only the first range started, resumes successfully and compares the complete output bytes. This prevents the size hardening from rejecting valid partial progress.

Other checked boundaries: refresh operates only after the task has stopped and workers have settled; replacement preflight precedes task mutation; a failed journal update restores the old task and RAM headers and queues persistence of that restored state. Replacement URLs must keep the source origin, direct continuation also compares the probed final origin, and HTTP responses are checked before appending bytes. Ranged transfers send `If-Range`; HTTP 200/416 or an invalid range fails while preserving committed bytes instead of truncating and restarting. A replacement cannot supply output/checkpoint paths. HLS requires the same selected manifest and resolved resource identity. External replacement retains its original source binding hash, verifies canonical YouTube identity or DASH manifest/base identity, and keeps extracted signed URLs in memory rather than adding them to checkpoint metadata.

Verification inspected: the reviewer ran the focused external refresh/resume tests after the legacy-base fix, with 19/19 passing, including the pinned-tool DASH continuation test. The integrating agent's recorded final core regression run passed 47/47, external run passed 34/34, and full coverage run passed 188/188 plus the actual Electron desktop test. Aggregate coverage was 97.80% lines/statements, 86.53% branches and 94.79% functions. These results concern the current source; final packaged and public-video execution outcomes belong in the release verification report.

Limits: Task 2 enables validated continuation for direct HTTP, including HTTP media files. The external adapter still refuses an unfinished plain HTTP video/muxed or standalone audio partial without a persisted validator/range contract; the presence of an aria2 control file alone does not enable it. The existing exception can restart unfinished M4A audio when a completed MP4 is retained. Legacy DASH caches with retained payload and no resource-base proof are preserved but cannot safely resume or refresh; the user must create a new task to download afresh. Generic HLS refresh remains strict and can reject changed signed resource URLs even when the video appears similar. Credentials are not persisted, and this work does not add authenticated YouTube, browser credential reconnection, arbitrary power-loss guarantees or native Linux/macOS verification.
