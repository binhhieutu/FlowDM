# Media continuation review, 2026-10-24

Scope: the 0.5 persistent-media delta in download manager/storage, HLS checkpoint/parallel transfer, external checkpoint/metadata adapter, and focused regression tests. Read-only implementation review; no broad test rerun or release certification.

Verdict: no unresolved P1/P2 findings in this bounded pass after the following fixes.

| Finding | Resolution checked |
| --- | --- |
| HLS checkpoint identity ignored changed timing/sequence when segment URLs stayed equal. | Selected media-manifest bytes now have a SHA-256 identity included in the checkpoint; direct helper callers retain a semantic fallback. |
| Pausing during external checkpoint preparation could start a transfer child after the abort signal had already fired. | Transfer checks abort immediately before spawn and again after listener registration. Regression aborts from initial cache-progress notification and confirms no transfer-child marker appears. |
| External mutable checkpoint media could be hard-linked outside the cache while passing byte/hash checks. | Directory entries and opened file handles require a single link; saved state receives the same regular-file checks. Regression rejects hard-linked media and metadata before transfer. |
| An unvalidated plain HTTP video partial could be deleted and the full video silently restarted. | The helper validates all plain partials before deleting anything. Video/muxed partials and standalone audio partials now refuse continuation while retaining bytes/control state. Only unfinished M4A audio may restart when a nonempty completed MP4 already exists. Negative regression cases cover retained video and audio-only data. |

Additional checks: checkpoint paths derive from task IDs; ordinary pause/close waits for workers or child exit before durable state snapshots; saved resources use bounded metadata, byte/hash checks and ordered reconstruction; changed sources or damaged/missing state refuse continuation rather than silently restart; cancel/success clear the task-owned cache; journal v4 accepts v1-v3. HLS keeps atomic checkpoint replacement with bounded Windows sharing-violation retries and refuses unreferenced stable fragment files. External native state reconciles its committed fragment prefix; unvalidated HTTP video/muxed partials retain bytes and report unsupported continuation. YouTube pins selected format and finite HLS timing/fragment order while allowing refreshed signed tokens; raw extracted CDN URLs are not written into the new checkpoint JSON.

Reviewer verification: four targeted external tests passed (format/manifest identity, bounded manifest preflight, hard links, initial-progress abort), plus the targeted YouTube HLS semantic-identity test. Root and implementation lanes own broader integration, actual pause/relaunch video tests, coverage and packaged-build results.

Final finite delta inspection: the HLS durable-resource notification now occurs after checkpoint commit and before ordered output append. It reports zero newly committed bytes, and the manager retains a separate append offset and cumulative-byte high-water mark; no additional P1/P2 issue found. The out-of-order fixture now synchronizes on that public notification instead of repeatedly opening checkpoint JSON. The optional portable smoke path also checks pause, full app relaunch, restored progress, resumed resource/byte reuse and final SHA-256 against the fully decoded sample; inspection found no additional P1/P2 issue in this harness. This was an inspection only, with no redundant broad test run.

Portable harness follow-up: an instrumented actual run subsequently isolated a launch race before the YouTube stage: the CDP endpoint became ready before Electron created its first page, so indexing `pages()[0]` produced an undefined page on the second launch. The harness now retains the browser immediately after connecting, waits for the first page when none exists, and records the page before waiting for UI readiness. Shutdown also waits for the actual browser process as well as the portable launcher, and can recover the created page for graceful cleanup. Static inspection confirms this addresses the observed launch race without app runtime changes. The actual portable rerun outcome belongs in the release verification report; this note does not claim that pending run passed.

Limits: this review does not promise continuation after arbitrary power loss or universal mutable-source support. A fragment still in flight may restart. Unvalidated HTTP video/muxed or audio-only partials retain bytes and refuse continuation; unfinished M4A audio can restart when completed video is already retained. Malformed or ambiguous checkpoints retain bytes and report an error. Same-user process inspection of tool argv remains the existing local privacy boundary.
